## 2026-03-19 — Gen 1 API Removal and Codebase Cleanup

### Context
The codebase had accumulated a significant amount of dead code from an earlier "Gen 1" simulation API that had been superseded by the current "Gen 2" API (`initialize_sim` / `run_sim!`). A full codebase survey was performed and results were compiled into `CLEANUP.md`, where decisions were made on each item before executing deletions.

### What was done

**Identified and deleted Gen 1 API (aerostructural.jl)**
The original simulation API — `initialize()`, `initial_condition!()`, `take_step!()`, `simulate()`, `simulate!()` — was removed. These were replaced by `initialize_sim()` and `run_sim!()`, which use `GXBeam.initialize_system!()` + `GXBeam.step_system!()` (Newmark-Beta) instead of the Gen 1 `GXBeam.take_step()` (backward Euler on the DAE). The Gen 1 functions had already been commented out pending removal.

**Deleted legacy GXBeam functions (gxbeam.jl)**
- `gxbeam_initial_conditions()` and `gxbeam_initial_conditions!()` — initial condition helpers that only the Gen 1 API called
- `simulate_gxbeam()` — standalone structural-only transient simulation, subsumed by `run_sim!()`
- `steady_simulate_gxbeam()` — standalone structural-only steady simulation, subsumed by `static.jl`

**Deleted legacy utility functions (utils.jl)**
- `prepareextra()`, `saveextra()`, `readextra()` — file I/O helpers from an early development phase, never called
- `plotdshistory()` — debug visualization helper, never called
- `sub_brent()` — custom Brent root-finder translated from OpenFAST, superseded by FLOWMath's Brent solver, never called

**Deleted legacy dynamic stall files**
- `src/beddoesleishman.jl`
- `src/beddoesleishman_aerodyn.jl`
- `src/beddoesleishman_gonzalez.jl`

These were local implementations of three Beddoes-Leishman dynamic stall variants from before the package adopted `DynamicStallModels.jl`. They were never `include()`d in `WATT.jl` and thus already inactive.

**Updated CLAUDE.md**
- Removed `beddoesleishman*.jl` from the file tree
- Updated `aerostructural.jl` description to reflect the active Gen 2 API

### Deferred items (see CLEANUP.md)
Several items were flagged but not acted on:
- `solve_BEM!()` has two implementations with slightly different signatures (with/without `phi0`); needs investigation before consolidating
- `thrusttorque()` / `ccthrusttorque()` in `bem.jl` — dead but deferred
- `derivative_me()` / `mat_derivative()` in `utils.jl` — pre-AD finite-difference utilities, deferred
- `get_aerostructural_velocities()` first overload in `environments.jl` — broken/dead, deferred
- `initialize()` naming collision across `static.jl` and `aero_only.jl` — deferred rename
- `initialize_ds_model()` return count — flagged for verification (Gen 2 code unpacks 4 values)
- `run_sim()` empty stub in `aerostructural.jl` — marked `fix`, not yet implemented

- **AD pattern landed (this is the load-bearing finding)**: end-to-end AD through `run_sim!` works only via the GXBeam parameter-vector approach mirrored from Cardoza2026's `fatigue_analysis!`. Pack per-element compliance + mass into `p`, define `pfunc(p,t)` that rebuilds a dual-typed `Assembly` + `distributed_loads` on every step, and a `prepp!(p, Fx, Fy, Mx)` callback that writes the dual-typed aero outputs into `p`'s load slot. Pass the non-dual skeleton `assembly` to `initialize_sim` for preallocation only; the dual assembly comes from `pfunc`. Also promote `blade.c` / `blade.twist` to the dual eltype so WATT's `find_inittype` allocates dual `gxhistory`/`aerostates` storage. Naively calling `ForwardDiff.derivative(pitch -> run_sim!(...).Fx, 0.0)` errors at `step_system!` because `system::DynamicSystem{Float64}` rejects duals — this is misleading; it's a usage error, not a WATT/GXBeam limitation. Plan.md Phase 2 deferred-bugs section should be updated next session to reflect this.
- AD verification approach: BEM unit-level uses `FiniteDifferences.central_fdm(5,1)` against a single scalar; coupled `run_sim!` uses a **directional derivative** check (random unit vector over compliance+mass region, scaled per-entry by `|p0|` because values span ~10 orders of magnitude). Per-entry spot checks were flaky due to symmetry of compliance/mass and dramatic scale variation; the directional approach integrates those out into one FD call. Tolerance kept wide (`rtol=1e-2`) — 3-step coupled FD is noisy.

## Session — 2026-07-15 (GPU BEMT v1)

- Built a GPU-batched BEMT for use alongside the GPU structural surrogate. Plan file: `~/.claude/plans/alright-let-s-make-a-tidy-kernighan.md`. Backend-agnostic via KernelAbstractions.jl; fixed-iteration Brent (no early exit) inside the kernel; airfoil `cl`/`cd` pre-sampled onto a uniform α grid at `BladeGPU` construction (linear interp on device). - **Why GPU-friendly**: ADG update is a pure explicit 32-state recurrence (no root-find, no implicit solve) — just algebra + `exp()` + table lookups + data-dependent branches. Only `y[1]=U` and `y[3]=aoa` are read (Udot/alphadot unused by ADG). Unlike BEMT (stateless per solve) DS is stateful across time → kernel launches once per timestep over `(section, sim)`, reading step `i-1`, writing `i`; serial launch loop queues in-order on the backend stream, single final synchronize.
- **Ported functions** (`src/dsmodel_gpu.jl`, all `@inline` backend-agnostic, single source of truth for both KA kernels and any CPU loop): `ds_step_adg` ← `update_states_ADG!`, `ds_loads_adg` ← `BLADG_coefficients`, `ds_init_adg` ← `initialize_ADG`; ADGSP `separationpoint`/`chordwiseseparationpoint` and `blend_cosine` inlined. cl/cd/cm pre-sampled onto a uniform α grid at `DSAirfoilGPU` construction (linear interp on device, `ds_af3` shares the bracket across all 3 tables) — same approach as bemt_gpu.
- **GPU-safety gotchas (load-bearing)**: (1) `sqrt` args guarded with `max(x,0)` — the KA *CPU* backend runs real Julia and `sqrt(neg)` throws `DomainError` (GPU would give NaN); guarding is a safe superset since the reference never drove those negative. Applies to `beta=sqrt(max(1-M²,0))`, `sqrt(max(fpp,0))`, `sqrt(max(fppc,0))`. (2) `M>1` early-out (`states .= oldstates; return`) became a masked select `M>1 ? sold : snew` at the end (no early return in a kernel). (3) Tuple I/O: read old states via `ntuple(k->xds[k,j,s,im1], Val(32))`, write via `Base.Cartesian.@nexprs 32` — both compile-time-unrolled to constant indices; dynamic indexing of a homogeneous tuple would spill/fail on GPU. (4) Per-section constants packed into one `(23, nsec)` matrix `consts` with named `C_*` index consts (one array to move/adapt, coalesced-ish reads) rather than ~23 separate vectors.
- **Unused old-states**: `sold[24]` (fppc_m) and `sold[25]` (fppm_m) are NOT fed back by the ADG recurrence — only `fpp_m` (state 23) is, via the TESF test and sigma1. Dropped those two bindings.
- **Two-gate validation strategy** (because GPU uses linear-table interp, CPU reference uses Akima splines — a naive 1e-10 gate is impossible): **Gate 1 (device correctness)** = KA march on selected backend vs KA march on `Array` backend, identical `ds_*_adg` code → isolates pure backend/FP. On CPU backend: **bit-identical (Δ=0)**. **Gate 2 (logic fidelity)** = CPU march vs stored Akima golden trace → residual is the linear-table-vs-Akima interp error, NOT a port bug. Result: loads within **~3e-4** (worst in transitional `moderate`/`light_stall` where the polar is sharply curved near stall), continuous states ~1.3e-3 (worst = chordwise sep states 18/21/24 where sqrt+fclimit clamp is most interp-sensitive), **1 boolean flip / 150k** (interp tipping a threshold tie — benign). Boolean states (29–32) counted separately, never lumped into continuous error.
- **Warp-divergence study** (portable estimator, user's chosen method — no profiler): re-derives each branch selector (sigma1/sigma3 trees, Nv 3-way, M>1) from the marched history, groups `(section,sim)` into launch-linear warps (`lin = j+(s-1)·nsec`, column-major KA order), flags non-uniform warp-steps. Indexing cross-checked by recomputing TESF/VRTX from history and matching stored states (0 mismatches). **Finding**: logical divergence is HIGH (sigma1 89%, sigma3 82%, ANY ~96% of warp-steps) BUT those branches only *select a scalar Tf/Tv factor* → trivial-body → SIMT predication, not serialization. The only heavyweight-body branches (Nv 3-way, M>1) diverge **0%** (Nv uniformly 'normal'; M=U/a≪1 for a turbine). **Recommendation: accept the divergence, do not sort/split kernels.** Definitive confirmation deferred to Nsight warp-efficiency on the H200.

Branch coverage verified: `attached_low` LESF=0/VRTX=0 (attached) → `deep_stall` LESF=1/VRTX=0.99 (fully separated), `light_stall` mixed. Committed reference `examples/data/gpu_dsmodel_reference.jld2` (~11 MB, JLD2 already in examples/Project.toml — no new dep) is **untracked**; regenerate via the reference script (reproducible). Warp study generates its own larger 36-sim batch at runtime.
